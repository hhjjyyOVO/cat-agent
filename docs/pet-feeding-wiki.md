# 宠物喂食建议计算器 Wiki

## 1. 模块简介

这是 Cat Agent 中的“宠物体况咨询 + 喂食建议计算器”模块。

它分成两部分：

- 聊天咨询：根据用户输入的宠物信息，给出体况、肥胖风险和管理建议。
- 喂食计算器：上传宠物粮营养成分表，结合宠物数据计算每日热量和每日喂食量，并可调用 LLM 生成更自然的建议。

这个模块的目标不是替代兽医，而是帮助用户更快得到可执行的饲喂参考。

## 2. 页面能力

- 默认显示聊天区，喂食面板默认折叠，不影响正常对话。
- 顶部按钮“喂食”可以展开/收起喂食面板。
- 支持快捷键 `Ctrl + Alt + F` 快速切换喂食面板。
- 支持上传营养成分表图片。
- 支持粘贴 OCR 文本作为图片识别失败时的补充输入。
- 支持选择目标：
  - 自动判断
  - 维持体重
  - 减重/控肥
  - 增重/恢复
  - 幼宠成长
- 支持设置每日喂几餐。

## 3. 主要流程

1. 用户填写宠物信息。
2. 用户上传宠物粮营养成分表图片，或粘贴 OCR 文本。
3. 系统读取容器内模型配置文件，确定 `BASE URL`、`API KEY`、聊天模型和识图模型。
4. 先解析营养表，提取代谢能、粗蛋白、粗脂肪、水分等字段。
5. 根据宠物体重、年龄、绝育状态、活动量和目标，计算：
   - RER：静息能量需求
   - DER：每日能量需求
   - 每日喂食克数
   - 每餐喂食克数
6. 如果配置了可用 LLM，再生成一段更自然的喂食建议。

## 4. 配置文件

模型和接口配置统一放在：

`data/ai_models.txt`

示例：

```txt
API_BASE_URL=https://api.openai.com/v1
API_KEY=填写你的模型平台密钥
CHAT_MODEL=gpt-4o-mini
VISION_MODEL=gpt-4o-mini
```

字段说明：

- `API_BASE_URL`：OpenAI 兼容接口地址。
- `API_KEY`：对应平台的 API Key。
- `CHAT_MODEL`：聊天建议模型。
- `VISION_MODEL`：图片识别模型。

支持别名：

- `BASE_URL`
- `OPENAI_BASE_URL`
- `OPENAI_API_BASE`
- `OPENAI_API_KEY`
- `LLM_MODEL`
- `IMAGE_MODEL`
- `OCR_MODEL`

如果 `data/ai_models.txt` 不存在，程序会自动生成默认模板。

### 系统提示词配置

系统提示词统一放在：

`data/system_prompts.txt`

文件按区块分别配置三类模型行为：

- `[CHAT_SYSTEM]`：普通宠物咨询对话。
- `[FEEDING_SYSTEM]`：结合计算结果生成喂食建议。
- `[VISION_SYSTEM]`：识别宠物粮营养成分表图片。

提示词文件通过 Docker 的 `data` 目录挂载到容器内。程序会在处理请求时读取文件，因此修改提示词后通常不需要重建镜像或重启容器。

## 5. API 接口

### 5.1 聊天接口

`POST /api/chat/stream`

用途：宠物体况咨询和对话式问答。

请求体示例：

```json
{
  "session_id": "test",
  "message": "我家英短，5岁，6.8kg，已绝育，平时不太爱动，我该怎么调整喂食？"
}
```

返回：SSE 流式文本。

### 5.2 喂食计算器接口

`POST /api/ai/feeding`

用途：根据宠物信息和营养表计算喂食建议。

支持两种提交方式：

1. `multipart/form-data`
2. JSON

表单字段：

- `session_id`
- `pet_text`
- `label_text`
- `goal`
- `meals_per_day`
- `image`

JSON 示例：

```json
{
  "session_id": "test",
  "goal": "weight_loss",
  "meals_per_day": 2,
  "pet_profile": {
    "species": "cat",
    "breed": "英短",
    "age_months": 56,
    "weight_kg": 6.4,
    "body_condition_score": 7,
    "neutered": true,
    "activity_level": "低"
  },
  "label_text": "代谢能 3600 kcal/kg，粗蛋白 32%，粗脂肪 16%，水分 10%"
}
```

返回内容包括：

- 解析后的宠物档案
- 解析后的营养表信息
- RER / DER
- 每日喂食量
- 每餐喂食量
- LLM 生成的自然语言建议

## 6. 计算逻辑

### 6.1 RER

RER（Resting Energy Requirement）用于估算静息状态下的基础能量需求。

常见公式：

```text
RER = 70 × 体重(kg)^0.75
```

### 6.2 DER

DER（Daily Energy Requirement）是在 RER 基础上乘以状态系数得到的每日能量需求。

示意：

```text
DER = RER × 系数
```

系数会结合以下因素调整：

- 宠物种类
- 是否绝育
- 活动量
- 目标类型（维持、减重、增重、成长）

### 6.3 克数换算

如果营养表中识别到了代谢能，就可以把 kcal 进一步换算成克数。

换算思路：

```text
每日克数 = 每日热量 ÷ 每克提供的热量
```

如果识别到的是：

- `kcal/kg`
- `kcal/100g`

系统都会尝试换算成每克能量后再计算份量。

## 7. LLM 生成建议

计算器先给出确定性的数值，再把以下信息交给 LLM：

- 宠物档案
- 营养表结构化结果
- RER / DER
- 每日和每餐份量

LLM 的作用是把结果写得更自然，更适合用户直接执行。

如果 LLM 不可用，系统会自动回退到规则版建议，确保页面仍然可用。

## 8. 页面交互

- 喂食面板默认折叠。
- 点击“喂食”按钮展开。
- 再点一次可收起。
- `Ctrl + Alt + F` 也可以切换。
- 计算结果直接显示在面板下方。
- 聊天区仍保留在页面下半部分，可继续正常咨询。

## 9. 安全提示

本工具只提供喂食和健康管理参考，不替代兽医诊断。

如果宠物出现以下情况，建议先就医：

- 持续呕吐
- 腹泻或便血
- 精神明显变差
- 呼吸异常
- 明显不吃
- 快速消瘦或快速增重

## 10. 常见问题

### 为什么有时只给出热量，没有精确克数？

因为图片里可能没有识别到代谢能，或者 OCR 文本不完整。

### 为什么 LLM 回复会回退成规则版？

通常是以下原因之一：

- `API_KEY` 没填
- `API_BASE_URL` 不可访问
- 模型名写错
- 网络连接失败

### 可以换别家模型吗？

可以。只要是 OpenAI 兼容接口，修改 `data/ai_models.txt` 即可。

### 配置改完后要不要重启？

容器重启后一定会生效；如果只是本地开发环境，建议刷新页面后再试。
